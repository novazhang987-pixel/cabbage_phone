# 食材库 · 手机版（离线可用）

> 记录家里有什么食材、什么时候过期、还剩多少。
> **数据存在这台手机里，不联网也能用。**

<sub>Offline-first pantry manager that runs entirely in the browser — no server, no account, no network required.</sub>

---

## 它是什么

电脑版那套后端（FastAPI + 数据库）被完整搬进了浏览器：

- `localdb.js` 拦截页面的 `fetch('/api/...')`，把后端接口用 `localStorage` 就地实现；
- `parser.js` 是「一句话拆字段」的规则解析（从后端 `app/parser.py` 一比一移植，23 个例句结果逐字一致）；
- 界面（`app.js` / `style.css` / `i18n.js` / `index.html`）与电脑版**同一份代码，一行没改**。

所以这个版本：

| | |
| --- | --- |
| 需要服务器 / 云平台 / 账号 | **都不需要** |
| 需要联网 | **不需要**（装了以后飞行模式也能用） |
| 功能 | 增删改查、临期提醒、数量增减、消耗流水、周报月报、回收站、购物清单、语音与打字录入、中英切换、导入导出 |
| 怎么装 | 发布成静态网站 → 手机浏览器"添加到主屏幕" |

## 怎么放到手机上（三步）

### 1. 发布到免费静态托管

**方式 A：GitHub Pages（用你现有的 GitHub 账号）**

1. GitHub 新建仓库，比如 `food-phone`，**选 Public**（免费版 Pages 只能公开）；
2. 把本文件夹里的文件（**不含 `tests.mjs`**）拖进仓库上传，提交；
3. 仓库 → `Settings` → 左侧 `Pages` → Source 选 **`Deploy from a branch`**，
   Branch 选 `main`、目录选 **`/ (root)`** → `Save`；
4. 等 1~2 分钟，得到网址：

   ```
   https://你的用户名.github.io/food-phone/
   ```

**方式 B：腾讯云 EdgeOne Pages（国内访问更快）**

国内打开 GitHub Pages 有时会比较慢。用腾讯云 EdgeOne Pages 新建静态项目、上传同样这些文件即可，
免费额度够个人用，域名是国内节点。

### 2. 在手机上装到桌面

1. 手机浏览器打开那个网址（**必须是 https**，否则装不了、也不能用语音）；
2. 添加到主屏幕：
   - **安卓 Chrome**：右上角菜单 →「安装应用」或「添加到主屏幕」
   - **iPhone 必须用 Safari**：底部中间的分享按钮 →「添加到主屏幕」
3. 以后从桌面图标打开就是全屏 App，**飞行模式照常使用**。

### 3. 把电脑版的数据搬过来（可选）

1. 电脑版 → **报表** → **导出备份** → 得到 `food-backup-日期.json`；
2. 把文件传到手机（微信「文件传输助手」最省事）；
3. 手机版 → **报表** → **导入备份** → 选那个文件 → 确认。

反过来也行：手机版导出的文件可以直接导进电脑版（两个方向都实测过，中文、引号、日期、流水全部无损）。

> ⚠️ 导入是**覆盖**：会用备份文件替换手机上现有的全部数据。导入前先导出一次当保险。

## 数据在哪、怎么备份（很重要）

数据存在**这台手机的这个浏览器**里（`localStorage`），不在云上。所以：

- **换手机、清除浏览器数据、卸载浏览器 → 数据会丢**；
- 手机空间紧张时，系统也可能清掉浏览器存储。

**唯一可靠的保险是定期导出**：报表 → 导出备份 → 把 json 存到微信收藏 / 网盘 / 电脑。
几十 KB 而已，建议每周或每月导一次。

## 想改点东西

| 想改什么 | 改哪个文件 |
| --- | --- |
| 界面样式 | `style.css` |
| 界面文案（中英文） | `i18n.js` |
| 界面逻辑（渲染、交互） | `app.js` |
| 数据逻辑（增删改查、统计、报表） | `localdb.js` |
| 一句话解析（语音/打字录入） | `parser.js` |

改完**记得把 `sw.js` 里的 `VERSION` 加一**（`v1` → `v2`），否则手机上还是旧缓存。

## 本机自测

```powershell
node tests.mjs
```

64 项检查，模拟用户把功能全点一遍。它给 Node 造了一个浏览器环境（DOM、localStorage、Blob 下载），
加载的却是**真实的那几个文件**，所以界面逻辑和本地数据层都一起验证了。
